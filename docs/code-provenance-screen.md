# Agent-produced code provenance and license review

Screen date: October 28, 2026.

## Candidate

Use coding-agent history to connect changed code to its originating prompt or tool evidence, and identify likely public-source matches and license obligations before merge.

## Problem signal

The [CodeGenLink paper](https://arxiv.org/abs/2510.01077) describes a VS Code extension that suggests likely source links for code similar to automatically generated code and reports licenses when possible. GitHub's [agent governance contribution guidance](https://github.com/microsoft/agent-governance-toolkit/blob/main/CONTRIBUTING.md) tells contributors to review AI output for copied or closely adapted third-party code and incompatible licenses. These establish a recognized risk and prior research direction, not its frequency or buyer demand.

## Existing coverage

- [Tabnine provenance and attribution](https://docs.tabnine.com/main/welcome/readme/protection/provenance-and-attribution) documents checking generated code against public GitHub code and showing source repositories and license types.
- [JFrog snippet detection](https://docs.jfrog.com/security/docs/snippet-detection) documents function-level source matching for code copied from the web, another repository, or generated by AI, with license and vulnerability signals.
- [Git AI](https://usegitai.com/) documents linking changed lines to coding agents, models, and prompts.
- [DeepBlame](https://github.com/deepblame/deepblame) documents agent/session attribution, line-level blame, and source-linked session reports.
- [hashd provenance](https://coderica.com/product/provenance/) documents linking requirements, agent calls, reviews, and human decisions to code, with an in-toto/SLSA provenance export.

The candidate is therefore a composition of existing source-similarity, license, and session-attribution capabilities. A transcript-to-diff adapter would not establish a better review decision or lower review cost by itself. The listed project claims were not independently benchmarked here; this screen does not prove that every combined workflow works or that buyers are satisfied.

## Decision

Do not build a generic AI-code provenance or license scanner, and do not treat an adapter between these tools as a product wedge. Reopen only if a real repository contribution exposes a costly attribution decision that current source-matching and session-attribution tools cannot answer, and a same-case evaluation shows a material improvement in reviewer time or correctness. No such gap, prevalence, adoption, or willingness to pay is established by this screen.

Keep real transcripts, source code, personal paths, and identifiers outside this public repository. Any later public evaluation must use synthetic material or material with documented permission.
