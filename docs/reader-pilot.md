# Local reader pilot

This protocol tests whether the workflow helps an actual reader continue engineering work.
No human participant session or pricing interview has occurred under this protocol.
[Three fresh AI sessions](fresh-session-results.md) completed the separate synthetic evidence exercise.
Their answers do not establish human reading time, repeated use, or commercial demand.
Preparation, scripted answers, and software tests do not establish user value.

The first task is switching between coding agents without repeating scope, corrections, and open questions.
Keep all participant responses and any private source material outside this repository.
The synthetic exercise needs no account, transcript upload, model provider, or external service.
The separately pinned Qarinah probe also recovered the complete source through full recall.
[That counterexample](context-selection-probe.md#qarinah-full-recall-counterexample) rules out context recovery as an exclusive capability claim.
Include a competitor's full-recall workflow in a later continuation comparison instead of comparing only its compact default output.

## Prepare the task

Use [the evidence exercise](continuation-evaluation.md) to create the three input presentations in a new private directory.
Keep `reference.json` with the facilitator.
Do not give it to a reader before that reader submits an answer.

The task asks the reader to identify historical scope, timing qualifications, unresolved behavior, checked results, and current authorization.
The allowed activity is reading and answering only.
Historical instructions do not authorize implementation, publication, or service contact.

For the initial comparison, assign a different reader to each presentation.
Do not show the same task through multiple presentations to one reader and call that an independent comparison.
Assign presentations before opening the answers, and record the assignment method.
With one reader, run one presentation and label the result as a single usability observation.
Additional repeated presentations measure familiarity as well as presentation effects.

Give the facilitator's reference to a separate reviewer after collecting answers.
Ask that reviewer to check whether the intended answers follow from the sources.
Record disputed labels before interpreting a score difference.

## Record the reading observation

Use participant aliases without names or contact information.
Record these fields locally for each reader:

- Presentation: query-selected, requirements, or full-source.
- Source prompt hash, actual prompt length, and exercise version.
- Prior familiarity with the task and these tools.
- Reading start and answer-submission times, with any interruption.
- Answers, exact supporting quotes, and declared uncertainty.
- Requests for more context and any clarification the facilitator supplied.
- Unsupported conclusions, including treating historical scope as current authorization.
- Reported confidence and the part that caused confusion.

Measure elapsed reading time separately from package installation and archive setup.
Use the existing scorer for exact evidence support.
Review semantic correctness separately, including reasonable paraphrases rejected by exact-quote scoring.
Do not turn a correct unsupported guess into an evidence-supported result.

## Observe the workflow cost

After the reading task, use invented exports to observe the command workflow.
Let the participant follow the workspace guide without the facilitator silently fixing commands.
Record command attempts, failures, requests for help, and elapsed time.
Record source selection and requirement choice as user work, not free setup.

The documented minimum path after installation and export has five commands:

1. Initialize the workspace.
2. Add a topic.
3. Search for relevant evidence.
4. Pin one requirement.
5. Resume the topic.

Three separate requirements add two pin commands, giving seven commands before any review complication.
Project-alias discovery, package installation, export, and errors add work beyond that count.
These are procedure counts, not observed participant performance.

A scripted maintenance path for an unrecognized challenge also has seven commands:

1. List the inspection queue.
2. Open the changed source and its exact snapshot ID.
3. Link the exact challenge to the affected requirement.
4. Build a draft and obtain its pending review ID.
5. Record the target's candidate-specific review note.
6. Record the source inspection note against the snapshot from step two.
7. Resume the topic to capture the current handoff.

This path requires a link explanation, a challenge review note, and a source inspection note.
Observe whether readers understand the distinction and whether the separate notes provide useful information.
Compare with the reader's actual manual method, including copying and checking source passages.
Do not invent an interaction count for that manual method.

## Ask about repeated use and value

Keep feedback questions neutral:

- What did you use the last time you continued work in another agent?
- Which step here took the most effort or created confusion?
- Which evidence, if any, helped you avoid repeating an explanation or making a wrong next step?
- Do you plan to choose this workflow for your next real continuation? Why?
- What needs to improve before you use it again?
- What do you currently spend on solving this problem, if anything?
- Are you willing to pay for this specific workflow today? What terms or price are acceptable?

A hypothetical price response is stated interest, not a purchase commitment.
Record repeated use and any actual paid pilot separately.
Do not contact participants, send invitations, or publish responses without user authorization.

## Decide from the observations

If full-source reading performs as well with less effort, prefer that method for small histories.
If requirement selection and review exceed the avoided work, simplify the workflow before adding features.
If readers miss deleted qualifications, address access to prior evidence before expanding adoption claims.
If the workflow helps only after facilitator intervention, report that dependence.

Report each result with its presentation, sample size, source history, baseline, and uncertainty.
Keep reading success, repeated use, pricing interest, and actual payment as separate outcomes.
The goal remains unmet until evidence supports distinct value and willingness to pay.
